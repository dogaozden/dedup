## Flag alignment

Every tool is asked the same question. This is how each one has to be told to ask it; the reasoning behind each row is in `xbench/tools.py`.

| semantic                       | ours                                     | fclones                                       | jdupes                                    |
|--------------------------------|------------------------------------------|-----------------------------------------------|-------------------------------------------|
| recursion                      | always recursive                         | (default) recursive                           | -r                                        |
| minimum size                   | --min-size N (inclusive)                 | --min N (inclusive)                           | -X size+=:N (>= N)                        |
| hidden files                   | included                                 | --hidden                                      | (default) included                        |
| ignore files                   | no such concept                          | --no-ignore                                   | (n/a)                                     |
| symlinks                       | (default) never followed, never a member | (default) not followed, not reported          | (default) not followed                    |
| hardlinks                      | names collapse onto one record per inode | (default) no -H; still lists every name       | (default) no -H; lists one name per inode |
| proof of equality              | full byte comparison                     | hash only (metro, 128-bit, non-cryptographic) | (default) full byte comparison            |
| persistent cache (lane B only) | cache on (lane A passes --no-cache)      | --cache                                       | -y <db>                                   |
| threads                        | (default) machine parallelism            | (default) machine parallelism                 | (default) single-threaded                 |
| output destination             | --report-json FILE                       | -o FILE --format json                         | -j, stdout redirected to FILE             |
| empty-tree output              | normal JSON report                       | normal JSON, groups: []                       | plain text, -j ignored                    |
| progress reporting             | (default) quiet when not a tty           | --progress=false                              | -q                                        |

### Differences no flag can close

- **Hardlinks are printed differently.** fclones lists every name a hardlinked inode wears; ours and jdupes list one. Correctness is therefore judged on inodes (`lstat` on every reported path) rather than on names, which is fair to all three. The raw path counts still differ and that is a real difference in what each tool tells a user.
- **fclones does not prove equality.** It groups by a 128-bit non-cryptographic hash (metro, its default) and never compares bytes. Ours and jdupes both read to confirm. fclones is doing strictly less work for an answer that looks the same, and its speed should be read with that in hand.
- **jdupes has no native minimum-size flag.** It is given `-X size+=:N`, an extension filter, which is inclusive of N and was verified to match `--min N` and `--min-size N` on a planted tree.
- **XBENCH.md's premise about caches is out of date.** The spec says fclones has no persistent cache. fclones 0.35.0 ships `--cache` and jdupes ships `-y <db>`; lane B enables all three rather than only ours, which is the fairer contrast the spec was reaching for.
- **czkawka is absent.** not installed. The Homebrew formula pulls 15 dependencies including gtk4, ffmpeg and librsvg (it builds the GUI alongside the CLI), which is the cask/GUI baggage XBENCH.md excludes.

## What this suite does not say

- No geomean, and no single headline across tools. XBENCH.md forbids it: one crowned number invites gaming, and averaging across shapes hides the scenarios where we lose.
- fclones' times and ours are not buying the same guarantee. fclones groups by hash and never compares bytes; ours and jdupes prove equality by reading. See the flag-alignment table.
- jdupes is single-threaded by design. Its column is not a hardware result.
